# 健康档案库

编号化的个人健康档案（HR-001、HR-002……），已去除直接身份标识。任何大模型拿到链接都能阅读和解读。

## 档案结构

每份档案对应两个文件，位于 `records/`：

| 层 | 文件 | 内容 | 谁能改 | 怎么改 |
|---|---|---|---|---|
| 事实层 | `HR-xxx-facts.md` | 基本信息、用药、病史、化验、检查、就诊 | 仅维护人 | 新数据就添加；改错先在第 12 节登记原值；每次修改都更新“事实版本” |
| 评论层 | `HR-xxx-comments.md` | 各模型、医生、本人的解读 | 所有协作者 | 只能添加；编号评论不改、不删；只有顶部的“综合意见”可以重写 |

总目录见 [INDEX.md](INDEX.md)。能改文件的 AI 按 [AGENTS.md](AGENTS.md) 操作。

## 让任何模型读档案

把下面这段复制给 ChatGPT、Claude、Gemini 等能打开网页的模型（以 HR-001 为例）：

```
请阅读这份健康档案，按档案开头“给 AI 模型”的说明来解读，然后回答我的问题。
先用一句话复述事实版本、最近一次化验日期和评论层最新编号；哪个文件读不到就直说，不要猜。
事实层：https://raw.githubusercontent.com/washingtonshao-web/health-records/main/records/HR-001-facts.md
评论层：https://raw.githubusercontent.com/washingtonshao-web/health-records/main/records/HR-001-comments.md
我的问题：……
```

- 模型打不开链接时：在 GitHub 上打开文件，点 Raw，把全文复制粘贴给它。
- 刚更新完的档案，raw 链接最多要 5 分钟才能读到新版本。

## 把模型的解读存回评论层

1. 模型回答完，会输出一个**评论块**，第一行以 `### C-????` 开头。
2. 把评论块复制，粘贴到这份档案的评论 Issue 里提交（HR-001 → [Issue #1](https://github.com/washingtonshao-web/health-records/issues/1)）。
3. 约 30 秒后，机器人自动编号，把评论追加到评论层最上面，并在 Issue 里回复结果。

规则：

- **一条回复只贴一个评论块。** 多个模型的意见分开贴，连续贴也不会丢。
- **医生意见或本人意见手写时，第一行也要按格式写**，例如 `### C-???? · 2026-10-08 · 医生 · 提问人：本人`。
- 第一行不是 `C-????` 的留言（比如“收到”）不会写入。
- **编辑或删除 Issue 里的原评论，不会改动已入库的内容。** 写错了就重新发一条，在“回应”里注明“更正 C-xxxx”。
- 只有仓库所有者和协作者能在 Issue 里发言。本人要提交评论，需要先接受协作者邀请。
- 手机网页上也能完成。

## 更新事实

1. 拿到新报告时，把报告交给模型，让它输出“事实更新提议”。
2. 维护人对照原始报告核对，然后在 GitHub 网页上编辑 facts 文件，或者交给 Claude Code、Codex 修改并提交。
3. 修改时同步更新事实版本、第 12 节和 INDEX.md 的“最后更新”。

事实更新提议贴到 Issue 里，不会写进任何文件，机器人只会提醒维护人核对。这是有意的：模型识别错的数字不能自动变成“事实”。

## 定期整理

- 评论多了以后，让一个模型通读评论层，重写顶部的“综合意见”，写明依据的事实版本、覆盖到哪条评论、整理人。
- 评论超过 40 条时，把旧评论移到 `HR-xxx-comments-archive-1.md`（机器人编号会把归档文件计入，编号不会重复）。
- 事实层超过约 60 KB 时，把 3 年前的化验行移到 `HR-xxx-labs-archive.md`，正文留链接。文件太长时，网页模型可能截断。

## 新建档案

1. 在 Issues 新建一个，标题为 `HR-002 评论`，然后锁定（Lock conversation），这样只有协作者能发言。
2. 运行 `python scripts/new_record.py HR-002 <该 Issue 链接>`。
3. 在 INDEX.md 加一行，然后提交。

编号永不复用；停用的档案在 INDEX.md 里标为“停用”。

## 隐私约定

- 档案中不写姓名、病历号、证件号、住址、机构名；报告照片和 PDF 不放进本仓库，由维护人线下保存。
- 编号与真人的对应关系不放在本仓库，由维护人另行保管。
- 本仓库公开，公开范围包括所有文件、历史版本和 Issue。出生年份、国家、日期、罕见诊断等组合起来，熟人仍可能认出是谁。
- **删除不可逆。** Git 历史和 Issue 可能已被搜索引擎和 AI 抓取，要彻底撤回只能删除整个仓库。
- 本人提交评论时，建议使用不含真名的 GitHub 账号；写入档案的提交人只显示角色（维护人 / 协作者）。
- 新建档案前，先征得本人同意。
